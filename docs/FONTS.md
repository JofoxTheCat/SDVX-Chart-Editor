# Fonts

## Summary

| Role | Font | Licence | Where it comes from |
|---|---|---|---|
| UI font | **Roboto** Regular/Bold (+ Condensed) | Apache 2.0 | embedded in `ppy.osu.Framework`, registered by the base `Game` |
| Fallback 1: Latin-ext, Greek, Cyrillic, punctuation | **Noto Sans** Regular/Bold | SIL OFL 1.1 | generated by `tools/FontGen` → `src/SDVXEditor.Resources/Fonts/NotoSans/` |
| Fallback 2: Japanese (kana, JIS kanji), symbols, fullwidth forms | **Noto Sans JP** Regular/Bold | SIL OFL 1.1 | generated by `tools/FontGen` → `src/SDVXEditor.Resources/Fonts/NotoSansJP/` |

The family names and the fallback registration live in one place,
`src/SDVXEditor.Game/Graphics/EditorFont.cs` (`EditorFont.AddFallbacks`, called once from `EditorGame.load`).

## Decision (2026-10-25): Roboto, as shipped by osu-framework

The UI uses **Roboto** (Regular and Bold). It is already embedded in the
`ppy.osu.Framework` package and registered by the framework's base `Game`
class, so nothing is downloaded or bundled by this repo for it.

Roboto: Christian Robertson / Google, Apache License 2.0.

The framework's Roboto glyph store only contains 342 characters (ASCII,
Latin-1 and parts of Latin Extended-A; see `Fonts/bmfont.bmfc` inside the
framework DLL): **no Greek, no Cyrillic, no kana, no kanji, no fullwidth
forms.** Real song titles need all of those — `ΛμreoLe=RushØVER=E`,
`じゃすと・べりー・くいっくりー！`, `ジャベリン`, `～` — and rendered as `?`.
Hence the fallbacks below.

## Fallback fonts (2026-10-25)

### How osu-framework 2026.807.0 finds a glyph

Read from the framework source at tag `2026.807.0`
(`osu.Framework/Text/TextBuilder.cs`, `IO/Stores/FontStore.cs`,
`IO/Stores/GlyphStore.cs`, `IO/Stores/RawCachingGlyphStore.cs`, `Game.cs`):

- `TextBuilder.getTexturedGlyph` asks the font store three times:
  `Get("Roboto-Bold", c)`, then `Get("Bold", c)` (any store whose name *ends
  with* the weight), then `Get("", c)` (any store at all); only then the
  fallback character `?`. **Every font added to `Game.Fonts` is therefore
  automatically a fallback for every `SpriteText`** — nothing has to name it.
- `FontStore.Get` checks its own glyph stores in the order they were added,
  then nested font stores in order. Roboto sits in a nested store (`localFonts`)
  and is always matched by the first, name-exact lookup, so it keeps priority
  for every character it has. The weight lookup means Bold text falls back to
  `NotoSans-Bold` / `NotoSansJP-Bold`, Regular to the Regular files.
- Lookup is per UTF-16 `char`; characters outside the BMP (emoji) cannot be
  rendered by this framework version at all.
- Baselines are aligned per line (`TextBuilder.AddCharacter`), so a fallback
  glyph sits on Roboto's baseline as long as the `.bin`'s `base` is right.
- **There is no runtime TrueType/outline path in this version** — no
  `OutlineGlyphStore`, no FreeType (checked by searching the DLL). Fonts are
  glyph stores only: an AngelCode BMFont **binary** `.bin` (read with
  SharpFNT) plus PNG pages `<name>_<n>.png`, `n` zero-padded to the digit count
  of the last page. Only the **alpha** channel of a page is used
  (`RawCachingGlyphStore` converts each page to an 8-bit alpha cache file in
  the framework's cache storage on first use).
- The framework's own fonts were made with AngelCode BMFont at
  `fontSize=100` (the `.bmfc` ships inside the DLL); Roboto has
  `base=80`, cap height 60 px. `FontStore` scales by `1/scaleAdjust` (100).

### What is in the glyph stores

| Store | Characters | Rendered at | Shipped |
|---|---|---|---|
| `NotoSans-{Regular,Bold}` | Latin-1 sup., Latin Ext-A/B, IPA, spacing modifiers, Greek, Cyrillic, Latin Ext. Additional (Vietnamese), Greek Ext., general punctuation, super/subscripts, currency, letterlike, number forms — minus everything Roboto has, minus combining marks/controls. 1,537 glyphs per weight. | em 84 px (cap height = Roboto's 60 px), `base` 80 | 2 pages + .bin per weight, 2.0 MiB total |
| `NotoSansJP-{Regular,Bold}` | **Everything Shift_JIS/cp932 can encode** (JIS X 0208 level 1+2 kanji, kana, symbols, NEC/IBM extensions), halfwidth katakana, complete hiragana/katakana blocks + phonetic extensions, enclosed CJK / CJK compatibility, fullwidth forms, the symbol blocks U+2010–U+2BFF the font covers (arrows, ①, box drawing, ★♪♥, …) — minus Roboto and Noto Sans characters. 8,308 glyphs per weight. | em 50 px (0.6 × Roboto's), registered in a nested `FontStore` with `scaleAdjust` 60 so it comes out at the same em as Noto Sans | 6 pages + .bin per weight, 12.6 MiB total |

Total shipped: **14.6 MiB** (15,323,433 bytes) embedded in
`SDVXEditor.Resources.dll`.

Why this subset: cp932 is exactly the repertoire a title has once ksh2vox
wrote it into the game's Shift_JIS `music_db` (`cp932_safe()` folds the rest),
so it is the natural set for an SDVX tool; full Noto Sans CJK (~65k glyphs)
would be tens of MiB per weight. Hangul, Chinese-only hanzi and emoji are not
covered and still render as `?`.

Why 0.6 resolution for CJK: the editor never draws text anywhere near 84 px;
at 50 px em the glyphs still downsample cleanly to the 12–28 px the UI uses,
and it cuts the CJK pages from ~17 to ~6 MiB per weight. Change it with
`--cjk-resolution` **and** `EditorFont.CjkResolution` together.

At runtime the framework converts each page it touches into an uncompressed
alpha cache (`<app storage>/cache/fonts`, 2048 × height bytes per page, at
most ~60 MiB if every page of every weight is used).

### Regenerating

```
dotnet run -c Release --project tools/FontGen
```

- Downloads the six pinned files into `artifacts/fontgen/` (git-ignored),
  verifies their SHA-256, reads Roboto's metrics from the
  `ppy.osu.Framework` DLL of `$(OsuFrameworkVersion)`, rasterises every glyph,
  shelf-packs 2048-wide pages and writes `.bin` + `.png` + `OFL.txt` into
  `src/SDVXEditor.Resources/Fonts/{NotoSans,NotoSansJP}/` (stale files of the
  same asset are deleted first). ~25 s.
- Output is deterministic: two runs produce byte-identical files (verified).
- Options: `--out <dir>`, `--cache <dir>`, `--cjk-resolution <f>`;
  `inspect <file.bin | Family.Asset>` prints metrics of a generated or framework font.
- The tool is **not** in `SDVXEditor.sln`, so a normal build never restores its
  packages. Dependencies: SixLabors.Fonts 2.1.3 / ImageSharp 3.1.11 /
  ImageSharp.Drawing 2.1.7 (Six Labors Split License 1.0 — Apache 2.0 for
  open-source, transitive and small-revenue use; ImageSharp is already an
  osu-framework dependency), SharpFNT 2.0.0 (MIT, the library the framework
  reads `.bin` with). Only the rendered bitmaps ship; no tool code does.

## Why not Aller (the osu!stable font)

Checked against the licence text on Font Squirrel
(<https://www.fontsquirrel.com/license/aller>): the *Dalton Maag Ltd Free
Licence Agreement* plus the *Dalton Maag EULA v1.2* it refers to.

- The EULA defines a **"Digital Product"** and names a *computer game* as an
  example; using the font in one "requires a separate OEM/ISV licence".
  A distributed editor application falls under that.
- The free licence covers at most **25 users** ("Licensed Unit").
- **Derivative works** (any converted format) are not allowed except for
  document embedding and EOT web fonts. osu-framework renders bitmap glyph
  atlases (`.fnt` + texture pages), which would be such a conversion.
- Redistribution is only allowed as the verbatim original `.zip`.

So Aller cannot be shipped inside this application without buying a licence
from Dalton Maag. It is not downloaded and not in the repo.

## Adding another font later

Add a `Source` (URL pinned to a commit/tag + SHA-256) and a generation call to
`tools/FontGen/Program.cs`, regenerate, and register it in
`EditorFont.AddFallbacks` (or as a family of its own). Only fonts whose licence
permits embedding and conversion (OFL, Apache) qualify. Keep folder names
free of `-`/spaces — embedded resource names are mangled for folders.
